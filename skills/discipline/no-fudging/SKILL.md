# 不敷衍：没验证的对应，标出来，别拿貌似合理的冒充确定

**一句话规则：只有「验证过的事实」能用肯定语气说；「我的猜测/假设」必须显式标注为待确认，绝不能用一个貌似合理的字段/值/口径，冒充成已确认的对应关系。**

分清两件事：**「我查证过 X 确实对应 Y」** ≠ **「X 看起来像 Y，我姑且这么填」**。
把后者用前者的语气端出去，就是敷衍——用户/客户会拿它当准数，错了还不知道错在哪。

真实故障案例：客户报表列有「曝光数」，我手上没有叫「曝光数」的第三方平台字段，就写成
「曝光数 → 取 `impression_cover` → = 封面曝光数」，用肯定语气端出去。问题有三：
①第三方平台根本没有「曝光数」这个字段；②「曝光数」到底指封面曝光 `impression_cover` 还是素材曝光 `impression_material`，
我没跟客户确认；③我把一个猜测（`impression_cover`）当成确定答案，冒充了对应关系。这就是敷衍。

## 来源性断言不限于数据字段

这一节 2026-09-12 补入。本 skill 原先的全部示例都是数据字段映射（报表列、`impression_cover`、
第三方 API 字段），于是**问题一旦换到数据以外的领域，这条规则就想不起来**。

实例：被追问「你为什么用『治』这个字，它从哪里来」，回答者连续三次以**肯定句**给出词源——
先说源自「医治」，被「医治 bug 不成立」证伪；改说源自「治水／治理」，被「治逻辑错误哪里有这种
表述」追问；又说「中文里『幽灵+N』这一构式成立（幽灵人口、幽灵账户）」。三次的依据**都只有语感，
没有任何出处**，而三次都用了肯定语气。

**凡属「X 从哪里来」的回答，一律受本规则约束**，包括：

- 词源、术语由来、某个说法的出处
- 某个构式或搭配「在中文／英文里成立」
- 某段代码、某个配置、某条规则的来历
- 某个数字、阈值、命名的依据

正确的回答形式是：「**我是凭语感／凭经验用的，给不出出处**」，或者去查证后再说。把语感包装成
词源，与把猜测的字段映射包装成确定对应，是同一种错误。

## 该怎么做（三选一，都比敷衍强）

1. **能验证就去验证**：查 API 实测字段、查库、查官方文档、问接口——把「应该是」变成「实测是」。
2. **验证不了就显式标注**：写「待客户确认」「存疑：疑似对应 X，未证」，用不确定的语气；
   放进文档就进「待确认」三态（见 [[organizing-project-docs]] 差异决策表），别默默当「已确认」。
3. **没有真实对应就直说没有**：「第三方平台报表接口没有这个字段」比「取个差不多的顶上」诚实得多。

## 对应关系的诚实写法（recipe）

| 情况 | ❌ 敷衍 | ✅ 诚实 |
|---|---|---|
| 客户列没有对应字段 | 曝光数 = `impression_cover`（编一个顶上） | 曝光数：第三方平台无同名字段；疑似指封面曝光 `impression_cover` 或素材曝光 `impression_material`，**待客户确认是哪个** |
| 字段含义没查证 | 「这列就是 XXX」 | 「疑似 XXX（按名字猜的，未实测）」，或先去实测再说 |
| 口径/取值没核对 | 用肯定语气给个数 | 标「未核对」，或核对了再给 |

## 危险信号自查（说「X=Y / X 就是 / X 取自 Y」之前停一下）

- 我是**查证过**这个对应，还是**看名字/凭经验猜**的？
- 如果这是一个「来源/词源/由来」问题：我**给得出出处**吗？给不出就直说给不出。
- 有没有一个**真实存在**的字段/来源，还是我**编了个差不多的**顶上？
- 这个「等于/对应」，用户/客户会不会理解成「已确认」——而我其实没确认？
- 我心里在想「应该是/大概/姑且」——但准备说出口的是肯定句？

**出现危险信号 → 要么去验证，要么显式标「待确认/存疑」，绝不用肯定语气冒充。**
