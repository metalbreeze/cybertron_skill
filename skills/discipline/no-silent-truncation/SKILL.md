# 不静默截断：越界的输入要「校验+提示」，绝不偷偷改用户的数据

**一句话规则：用户输入违反约束（超长/超量/越界/格式错）时，必须 校验并明确告知（挡住或警告、列出违规项），让用户自己改；绝不 `.slice`/clamp/drop 把超限部分默默处理掉。**

静默截断 = 在用户背后篡改他的数据。用户以为存进去的是他打的那个，实际被你切成了残缺的另一个东西，还毫不知情——错了都不知道错在哪。这跟 [[no-fudging]] 同源：都是「拿一个貌似没问题的结果冒充用户的真实意图」。

## 真实翻车案例

词库单行词条 `cleanWord = s.replace(/\s+/g,'').slice(0, 20)`——用户输入一条超过上限的关键词
`很长的一段关键词……(超过上限)`，`.slice(0,20)` **悄悄只留前 20 字**，后面的字没了、意思都变了，
用户以为存的是完整词。客户验收原文：「单行词条**未在保存提交时做校验**」——他要的是**校验**，不是替他截断。
**修法**：去掉 `.slice` 静默截断 → 保存时 `word.length > 20` 就 `message.error` 列出违规词 + `return` 挡住保存。

## 该怎么做（按约束类型）

| 约束 | ❌ 静默截断 | ✅ 校验+提示 |
|---|---|---|
| 长度上限 | `s.slice(0, MAX)` 保存/commit 时切掉 | 不截，保存时 `s.length > MAX` → 弹提示列出违规项 + 挡住 |
| 列表条数 | 取前 N 条、悄悄丢弃其余 | 超 N → 提示「共 X 条、超出 N，请删减」或明确「只取前 N（并 log 丢了哪些）」 |
| 数字区间 | `InputNumber` 设 `min`/`max` 逐位输入被钳回（"改不动") | 不设硬 min/max，用软校验 `validateStatus`/`help` 提示区间 |
| 字符集/格式 | 悄悄剥掉非法字符（如标点、空格）改变原文 | 该保留的保留；只在明确必要时净化，且告知；格式错就报错让用户改 |

## 例外（可以「有损」，但必须**说出来**）
不是所有裁剪都禁止——文件名净化去非法字符、下载 TOP 上限截断 这类「有意的、有损的」处理**可以做**，
但前提是 **① 用户能预期（写在提示/extra 里）② 或运行时 log/提示说清「丢了什么、丢了多少」**。
判据：用户会不会误以为「全都存/全都取了」？会 → 必须提示；不会（已明示上限）→ 可截。

## 危险信号自查（写 `.slice(0, N)` / `min=` / `.slice(0, topN)` 之前停一下）
- 我这一刀切下去，用户**知不知道**被切了？不知道 → 换成校验+提示。
- 切掉后存/发出去的，还是**用户想要的那个**吗？不是 → 别切，报错让他改。
- 我是在「帮用户省事」还是在「替用户做了他没同意的决定」？后者 = 静默篡改。
- InputNumber 设了 min/max 导致中间值输不进去（"改不动")？→ 去掉硬约束，软校验提示。

**出现危险信号 → 把「静默处理」换成「校验并明确告知」，把决定权还给用户。**
相关：前端别放没有真实验证链路的控件；[[cross-layer-consistency]]（校验要跨层落实，不能只做在一层）。
