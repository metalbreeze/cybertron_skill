# 用户语言，不说内部黑话

**一句话规则：对用户提到任何业务对象，说「用户认得的名字 + 平台/业务 ID」，绝不说内部数据库序号、表内 id、开发代号。**

内部 id 是实现细节；用户认得的是账户名、平台 ID（如第三方平台的账户 ID）、素材文件名、人员姓名。
说「账户27」只会逼用户反问「什么是账户27?」——真实翻车案例：探针里刚用过
`ad_account_ids:[27]`，汇报时顺嘴说了"账户27"，用户完全不知所指。

## 用户可见的对象引用长这样（recipe）

`对象名称（平台ID）` —— 例：`示例客户A（平台ID 100000001）`

| 提到 | ❌ 内部黑话 | ✅ 用户语言 |
|---|---|---|
| 投放账户 | 账户27 / ad_account_id=27 | 账户名（平台ID xxxx） |
| 素材 | material_id=5 / photo 行 | 素材文件名（必要时附 md5 前几位） |
| 人员 | uploader_id=3 | 姓名或昵称 |
| 计划/组 | 我们表里的 id | 计划名称 + 平台侧 campaign_id |
| 问题/模块 | B 型坑 / §5.4 / #22 / F2 | 说全称（"显示≠下发"类 bug / 定向配置区域） |

## 手上只有内部 id 时

**先花一步查出名字再开口**（查库、查列表接口、查上下文），不要图省事直接复述 id。
实在查不到，明确标注这是内部编号并给可核对的线索：「数据库第 27 号账户记录（名称待查）」，
不能让用户猜。

## 内部 id 允许出现的地方

仅限**非用户读物**：代码、注释、日志、git commit、API payload、调试命令。
一旦文字是给用户看的（对话答复、UI、报错文案、报表、验收说明），一律翻译。

## 红旗自查（说出口前停一下）

- 「账户N」「id=N」「第N号」指代业务对象
- 刚在工具调用/探针里用过的参数值直接复述给用户
- 只有开发者才懂的编号、代号、任务号（#22）、章节号（§5.4）

**出现红旗 → 先翻译成 名称（平台ID）再说。**
